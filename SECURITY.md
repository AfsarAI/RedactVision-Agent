# Security & Privacy Policy

> **Project:** RedactVision Agent  
> **Team:** ByteForce  
> **Problem Statement:** SIH26171 — On-device Visual Perception for Light-weight Browser Agents  
> **Organization:** Indian Space Research Organisation (ISRO)

At RedactVision Agent, security and user privacy are fundamental architectural requirements, not afterthoughts. This document outlines our security model, threat mitigations, cryptographic guarantees, and responsible disclosure procedures.

---

## 🔒 Non-Negotiable Privacy Invariants

The RedactVision Agent is built around five core security invariants enforced at compile time and runtime:

1. **Zero Raw PII on the Network**: Raw personal identifiers (emails, phone numbers, real names, passwords, Aadhaar, PAN cards, credit cards) never cross the network boundary.
2. **Client-Side Token Map**: The mapping between semantic tokens and real values (`[PERSON_01] -> "Shrijal Gupta"`) is stored strictly in client-side memory and is never transmitted, logged, or serialized into network payloads.
3. **Hardware-Backed / AES-GCM Encrypted Vault**: Saved user profile data is encrypted on-device using **256-bit AES-GCM**. The non-extractable cryptographic key is generated and stored inside browser **IndexedDB** (`redactvision-private-vault`).
4. **Untrusted Server Reasoning**: Every action generated by remote reasoning servers (Groq, OpenRouter, OmniRoute) is treated as untrusted input. Actions must pass local schema checks, target verification, and risk policy checks before browser execution.
5. **No Secret Leakage in Logs**: Console output, network logs, telemetry, and error reports sanitize sensitive values and emit only semantic tokens.

## 🔑 Permissions & Least Privilege Principle

The Chrome Extension (Manifest V3) requests only the minimum set of permissions necessary for autonomous, privacy-preserving browser automation:

| Permission | Purpose & Scope |
| :--- | :--- |
| **`activeTab`** | Grants temporary access to the active webpage for DOM extraction and in-page UI injection upon user invocation. |
| **`tabs`** | Enables multi-tab subagent orchestration (`chrome.tabs.create`, `chrome.tabs.update`, `chrome.tabs.remove`) for fan-out tasks. |
| **`scripting`** | Injects necessary helper utilities and styles for the in-page chat panel. |
| **`storage`** | Stores encrypted AES-GCM profile vaults, local settings, and sanitized session history. |
| **`debugger`** | Connects to Chrome DevTools Protocol (CDP) to dispatch authentic OS-level mouse and keyboard events (`Input.dispatchMouseEvent`, `Input.insertText`) to interact with rich interfaces like ChatGPT and Google Forms without executing arbitrary scripts. |

## 🚨 Reporting a Vulnerability

We appreciate the efforts of security researchers and community contributors in keeping RedactVision Agent secure. If you discover a security vulnerability or privacy leak, please disclose it responsibly.

### How to Report

1. **Do NOT open a public GitHub issue** for security vulnerabilities.
2. Email your findings directly to the maintainers or report via **GitHub Private Vulnerability Reporting** on the repository page.
3. Include the following details in your report:
   - Description of the vulnerability (e.g., PII leak, prompt injection, bypass of validation).
   - Step-by-step reproduction steps or proof-of-concept (PoC).
   - Affected browser, OS, and extension version.
   - Any suggested mitigations or patches.

### Response Timeline

- **Initial Acknowledgment:** Within **48 hours** of receiving your report.
- **Triage & Assessment:** Within **5 business days**.
- **Fix & Disclosure:** Coordinated release and advisory published once the patch is verified.

## 🛠️ Security Best Practices for Contributors

- **Never Commit Secrets**: Never commit `.env` files, API keys, credentials, or private test data. The repository includes automated `.gitignore` rules and GitHub Push Protection for secret scanning.
- **Run Typecheck & Linter**: Ensure all code passes `npm run build` (`tsc --noEmit`) and Python syntax checks before submitting pull requests.
- **Verify Privacy Invariants**: Any PR altering `privacy-firewall.ts`, `pii-detector.ts`, or `mock_agent.py` must prove that raw values are never transmitted across the network.
